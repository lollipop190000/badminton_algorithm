# 에너지 타구·목표 구획 전략

## 1. 원인 / 하는 이유 / 개요

고정된 타구 정책의 잔여 예산 V를 타구·도착 구획 선택으로 확장한다. 최근 3타구 구획과 타구 교대, 양 선수 잔여 예산을 사용한다. 상대는 경험 정책을 따르고 전략 선수는 자신의 차례마다 재선택한다.

## 2. 과정

원 작업 폴더에서 `.venv-gru/Scripts/python.exe scripts/run_energy_strategy.py --run-id <고유 ID>`를 실행한다. 게시 저장소에서는 `python run.py energy-strategy --run-id <고유 ID>`를 사용한다. 기본 20/40구간 비교, 최대 160구간, 질의당 MC 20,000회다. `--resume`은 같은 입력·코드·설정 해시의 실행만 재사용한다. 원자료·기존 학습·BFMD 추출을 재실행하지 않는다.

내 행동은 8타구×16도착 구획이고 타구 선택 빈도를 조건부 행동 점수에서 제거한다. E/U/C는 기존 strict M0를 사용한다. 계속되는 타구는 목표 구획에 도착한다고 가정하며 목표 정확도·구획별 E/U 효과는 추정하지 않는다. 상대는 pi*T로 대응한다. 미래에는 에너지 의존 hazard를 사용할 수 있지만 현재 solver는 상수 M0를 확인하며 다른 모델을 조용히 D=0으로 고정하지 않는다.

지원은 train-only role pooling으로 계산한다. 조합 전체 continuation 50건 이상, 3→2→1타구 문맥 continuation 및 유효 비용 각 5건 이상이다. 짧은 문맥을 사용하는 경우 지원 수준을 표시한다. 모형 점수 동률(1e-12)에는 내 비용→지원 표본→기존 행동 번호로 결정한다. 추천 후보 없음은 경험 정책이다. 종결 추가 비용은 0, 한쪽 예산 소진은 그 선수 패배, 동시 소진은 중앙값 0.5이다. 하한·상한은 선택된 같은 정책을 평가한다.

BFMD 비용은 공식 lookup의 i,j,r,p,s 키로 읽으며 직접 상태 n=0과 fallback·외삽을 보존한다. 기존 거리와 BFMD 경로, 속력/방향전환/균형 가설을 비교한다. M3 beta0는 M0와의 대수 일치 검증용이고 unavailable M1/M2는 사용하지 않는다. 동일 절대 예산 비교와 비용별 train replay p50/p75/p95 비교는 별도다. 처음 세 타구 및 service 등 BFMD 키를 만들 수 없는 구간은 감사된 거리 비용을 유지하고 그 수와 출처를 기록한다.

공통 절대 예산은 기존의 완전 관측 train 소비량 백분위수를 그대로 읽는다. 비용별 replay는 프레임 정합성이 있는 train 랠리 전체에서 감사된 대체 소비량도 포함해 같은 모집단에 각 비용 모형을 적용한다. 따라서 replay의 거리 p95가 기존 관측 전용 p95와 조금 다를 수 있으며 두 백분위수를 같은 결과로 취급하지 않는다.

API `POST /api/energy-strategy`는 history(Z0..Z16, 최대 3개), current_hitter, strategy_player, cost_model, initial_a/b, remaining_a/b를 입력받는다. 모든 128개 행동과 16개 구획별 최선, 상위 3개, 경험 정책 대비 차이, 비용, 지원, 수치 검증 상태를 반환한다. `/api/energy-strategy/from-rally`는 선택 타구 **직전** 이력과 incoming 소비량을 계산하고 현재 행동·현재 목표를 미래 정보로 사용하지 않는다. `/api/energy-strategy/metadata`는 실행 ID·예산·모형·가정을 제공한다.

초기·잔여 예산은 유한 값이어야 하며 잔여는 초기 이하이다. M0에서 이미 소비한 에너지는 종료확률을 바꾸지 않으므로 초기 예산이 달라도 동일 잔여 예산 격자를 재사용한다. 잔여가 사전 계산 범위를 넘으면 422, 결과·큰 격자가 없으면 503과 재생성 안내를 반환한다. 유효 이력 3개 미만·Z0 이력은 추천하지 않고, 소진 상태나 상대 차례에는 상위 추천을 보류한다.

## 3. 결과

새 실행은 `outputs/energy_strategy/runs/<run_id>/`에 RUN.json, full action_scores Parquet, 추천 변화율, CQL 추천 비교, 수치/정책 비교, 비용별 예산, PNG 히트맵을 만든다. latest.json은 완료한 실행만 가리킨다. 큰 .npy 격자는 로컬에 보존하고 large_artifacts.json의 전체 크기·SHA256·생성 명령으로 재생성한다. 게시 결과는 05의 results/runs에 모은다. CQL Q는 확률로 변환하지 않는다. 모형 조건부 값과 rollout 비교를 실제 승률 개선이나 피로·대사 효과로 해석하지 않는다.
